## 6. 需要组内拍板 / 已知问题

### 6.1 CUDA 版本规则（有专门的报告）

Assignment-0 的 Windows 教程里写着「CUDA 版本超过 12.4 仍然选择 12.4」。
但实测发现：**这条规则在 RTX 50 系（Blackwell）显卡上会导致「装得上、但一训练就崩」**
（`torch.cuda.is_available()` 返回 `True`，实际运算报 `no kernel image is available`）；
换成 **cu128** 就正常。

👉 细节、复现步骤与解决办法都写在 **`Assignment0_CUDA兼容性问题报告.md`** 里。
教材目前的处理：**Windows 保留原规则 + 加一条 50 系提醒**，等组内结论后再改。

### 6.2 数据集是「增强过」的

本数据集的增强方式是**往数据集里加入新图片**（把真实目标和容易被误检的目标放在同一张图里），
**不是**对原图做旋转/裁剪。所以**不存在**「同一张图泄漏到 train 和 val」的问题。

### 6.3 几个容易被误读的细节（教材里已写明）

- **改 `conf` 几乎不影响 mAP**：因为 AP 本来就是在所有置信度上积分出来的；
- **混淆矩阵的归一化是按「列」（真实类别）算的**，不是按行；
- **「预测 ≠ 标签」不等于「模型错了」**：可能是漏标，也可能是标注规约与模型行为不一致。

## 7. 数据集（重要：**不在仓库里**）

### 7.1 它是什么

- **规模**：1308 张图（训练 1089 + 验证 219），全部 `.jpg`；
- **类别**：3 类 —— `baizi`、`cheli`、`shuiguo`；
- **标签**：标准 YOLO 格式（`class x_center y_center width height`，已归一化）；
- **来源**：由实验室提供（原始数据 + 已标注版本）。

### 7.2 为什么仓库里没有它

**因为它太大了**：`dataset/` 单独就占 **1.6 GB**（整个工作空间 1.6 GB，其它内容加起来才 64 MB）。

GitHub 对单文件有 100 MB 的硬限制（我们**没有**超标），但**建议仓库总体积不超过 1 GB**。
把 1.6 GB 的数据集提交上去，会让后续 clone / pull 非常痛苦，而且数据集本身也不适合用 Git 管理。

👉 因此仓库根目录的 **`.gitignore` 已经排除了 `dataset/`**。

### 7.3 你要怎么把它放回来

clone 仓库后，从实验室（或数据提供方）拿到 `dataset/`，**直接放到仓库根目录**，使结构变成：

```text
<仓库根目录>/
└── dataset/
    ├── dataset.yaml
    ├── images/train/   images/val/
    └── labels/train/   labels/val/
```

> 🚧 **待定**：数据集的正式获取方式（网盘链接 / 服务器路径 / 由谁提供）需组内确定后补在这里。

> ⚠️ **路径必须是这样**：教材里所有命令写的都是 `data=dataset/dataset.yaml`（相对仓库根目录）。
> 如果你把数据集放在别处，请自行修改命令里的路径。

### 7.4 关于 `dataset.yaml`（已经修好）

原文件里写死了**另一台机器**的绝对路径（`/home/andy/Workspace_YOLO_Training/...`），在别的电脑上根本跑不起来。
现在改成了**不写 `path`、`train`/`val` 相对本文件目录**的形式，整体拷到任何电脑都能直接用。

### 7.5 两个小提示

- 第一次训练后，`dataset/labels/` 下会自动生成 `train.cache` / `val.cache`（Ultralytics 的正常缓存，可加速下次训练；`.gitignore` 已排除）；
- 教材 2.3.7.4 讲的“视频连续帧数据泄漏”，本数据集**不存在**——它的“增强”是**往数据集里加入新图片**，不是对原图做旋转/裁剪。
