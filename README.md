### 3.5 视频目标检测示例：`nl_yellow视频检测.ipynb`

一份**综合示例**（不是作业）：把讲义第 3、5、6、10 章的东西串起来解决一个真问题 ——
在 `res/nl_yellow_video.mp4`（1280×720 / 25 fps / **475 帧** / 19 秒，白底多宫格动画）
里逐帧找出**黄色奶蛙**。

- **思路**：奶蛙是纯黄色、背景是白底 → **不需要深度学习**。
  「`COLOR_BGR2HSV_FULL` → `inRange` 黄色区间 → 开运算去噪 → 闭运算补洞 →
  `findContours` → `boundingRect` → 画框 → `VideoWriter`」就够了；
- **参数（已实测调好）**：HSV_FULL **H 25~55**、**S ≥ 60**、**V ≥ 120**；
  开运算 **9×9**、闭运算 **15×15**、`min_area` **3000**；
- **实测结果**（针对**当前**这个素材）：475 帧 **100% 有检出**，累计 **639 个目标**（平均 1.35 个/帧），
  每帧目标数分布 `{1: 313, 2: 160, 3: 2}`，最大目标面积 **347645 px²**；
  纯检测 **≈10.0 ms/帧（≈100 fps）**（不含写视频）；
- **产物**：跑一遍会生成 `out/nl_yellow_result.mp4`（约 5.9 MiB，475 帧标注视频；
  已读回校验 475 帧全部解出。**文件已随 `out/` 精简删掉，重跑即得**）；
- **⚠️ 换过一次输出格式（踩过的坑）**：最初写的是 `out/nl_yellow_result.avi` + `MJPG` ——
  OpenCV 能正常写、也能自己完整读回来，但**很多播放器打不开 MJPEG 的 AVI**。
  已改成 **`.mp4` + `mp4v`（MPEG-4）**：兼容性好得多，**文件只有原来的 1/4 左右**。
  → **`isOpened()` 返回 `True` 并不等于"这个视频别人打得开"**，这条已经写进 notebook 的注意事项；
- 文件里还带了**参数实验**（对比闭运算核 0/15/25 与 `min_area` 3000/5000/10000）
  和**常见坑自查**清单（`frameSize` 顺序、`release()`、`COLOR_BGR2HSV_FULL` 等）。

> ⚠️ **一处已知的小瑕疵**：宫格切换时，**画面边缘只露一条**的奶蛙会被单独框出来
> （当前素材里只有第 366、367 两帧有 3 个目标，多出来的那个是右边缘 **24 px 宽**的窄条、
> 仅 **3524 px²**，而正常一只 8~35 万 px²）。想干净点把 `min_area` 提到 1 万左右即可，
> 代价是画面边缘「只露半只」的奶蛙也会一起被丢掉。
>
> ℹ️ **这条是随素材变的**：换一版视频，"多出来的框"可能是过渡残影、也可能是边缘窄条。
> 所以 notebook 里**不写死这些数字** —— 参数实验那一格是当场算出来的。

### 3.6 命令行检测工具：`detect_nailong.py`

`nl_yellow视频检测.ipynb` 的同门**脚本版**（399 行），把同一套颜色分割封装成一个能直接用的命令行工具：

```bash
python detect_nailong.py                                    # 默认跑 res/nl_yellow_video.mp4
python detect_nailong.py -s res/nl_hd01.jpg -o out/hw.png    # 单张图
python detect_nailong.py -s res -o out/dir                   # 整个目录
python detect_nailong.py -s xxx.mp4 --csv out/stats.csv --save-mask --side-by-side
python detect_nailong.py --probe res/nl_hd01.jpg             # 打印采样点 HSV 值，帮你定阈值
python detect_nailong.py --demo  res/nl_hd01.jpg             # 复现任务书阶段六的三步测试
```

- **算法**和 §3.5 一样（`HSV_FULL` + `inRange` + 开运算 + `findContours` + `boundingRect`），
  但多了 `--roi`、`--min-fill`（用**填充率**剔掉细长条假目标）、`--max-targets`、`--stride`、
  `--csv`（逐帧统计）、`--save-mask`、`--side-by-side` 这些开关；
- **类接口对齐大作业阶段六**：`NailongDetector` 提供 `set_roi` / `mask` / `detect` / `annotate` /
  `to_config` / `from_config`，写在 `if __name__ == "__main__"` **之外**，可以被 `import` 复用；
- **中文路径的两个坑都绕开了**：`np.fromfile` + `imdecode` 读、`imencode` + `tofile` 写、
  `VideoWriter` 先写英文临时文件再 `os.replace`（正是讲义第 1 章讲的那两个坑）；
- ⚠️ **依赖 `Pillow`**（只为在画面上写中文，`cv2.putText` 画不了中文）。
  Assignment-0 装的 `requirement_opencv.txt` 里已经带了 pillow；
- ⚠️ **实测提醒（编码器）**：脚本的 `opened_writer()` 先试 `avc1`(H.264)、打不开才回退 `mp4v`。
  但在**这台机器**上 `avc1` 的 `isOpened()` 会返回 `True` 却**没有真正在编码**
  （实测约 **94 KB/帧**，475 帧约 **43.5 MB**），所以永远走不到回退分支。
  **在自己机器上跑完记得看一眼输出视频的体积**；想稳就把默认改成 `mp4v`；
- ℹ️ **画面上的那个百分比不是置信度**：它是 `轮廓面积 ÷ 外接矩形面积`（**填充率**），
  标签已经写明「填充率 xx%」。**颜色分割根本没有置信度这个概念** ——
  只有训练过的模型（YOLO 那种）才输出 confidence。**别让新人把这两件事混起来。**

### 7.2 现状

- **不在版本库里**：`.gitignore` 里有 `dataset/` 这条规则；
- **当前工作区里也没有这个目录**（`AGENTS.md` 记录它当时占 **1.6 GB**）。

### 7.3 你要怎么把它放回来

从实验室（或数据提供方）拿到 `dataset/`，**直接放到仓库根目录**，使结构变成：

```text
<仓库根目录>/
└── dataset/
    ├── dataset.yaml
    ├── images/train/   images/val/
    └── labels/train/   labels/val/
```

> 🚧 **待定**：数据集的正式获取方式（网盘链接 / 服务器路径 / 由谁提供）需组内确定后补在这里。

> ⚠️ **路径必须是这样**：教材里所有命令写的都是 `data=dataset/dataset.yaml`（相对仓库根目录）。
> 如果你把数据集放在别处，请自行修改命令里的路径。

### 7.4 关于 `dataset.yaml`（已经修好）

原文件里写死了**另一台机器**的绝对路径（`/home/andy/Workspace_YOLO_Training/...`），
在别的电脑上根本跑不起来。现在改成了**不写 `path`、`train`/`val` 相对本文件目录**的形式，
整体拷到任何电脑都能直接用。（原文件曾备份在 `/tmp/dataset.yaml.bak`。）

### 7.5 两个小提示

- 第一次训练后，`dataset/labels/` 下会自动生成 `train.cache` / `val.cache`
  （Ultralytics 的正常缓存，可加速下次训练；`.gitignore` 已排除）；
- 本数据集的「增强」是**往数据集里加入新图片**（把真实目标和容易被误检的目标放进同一张图），
  **不是**对原图做旋转 / 裁剪。所以**不存在**「同一张图泄漏到 train 和 val」的问题。

### 7.6 几个容易被误读的细节（YOLO 教材里已写明）

- **改 `conf` 几乎不影响 mAP**：因为 AP 本来就是在所有置信度上积分出来的；
- **混淆矩阵的归一化是按「列」（真实类别）算的**，不是按行；
- **「预测 ≠ 标签」不等于「模型错了」**：可能是漏标，也可能是标注规约与模型行为不一致。
